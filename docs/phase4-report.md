# Phase 4 implementation report

This report records the Phase 4 state. Phase 5 later replaced seeded current occupancy and session-only check-ins/reports; see [occupancy-system.md](occupancy-system.md).

Implementation is in place. A live browser check rendered OpenFreeMap tiles and selectable building markers. Native device acceptance still requires simulator/device QA.

1. **Implemented:** optional foreground location, nearby discovery, real distance labels, MapLibre adapters, building/floor selection, shared filters, proximity sorting, route fallback and external walking directions. Existing account, preferences and favorite flows remain functional.
2. **Geospatial architecture:** device location adapter/controller/context → existing typed mobile API client → FastAPI router/service/repository → indexed PostGIS geography. User position is transient request input.
3. **Provider:** `@maplibre/maplibre-react-native` for native and `maplibre-gl` for web, behind the existing `CampusMap` boundary. OpenFreeMap's dark style is the default and needs no key. The native SDK uses a development build; Expo Go is unsupported. Web workers are copied into `public/maplibre` on npm install.
4. **Files:** backend changes are in `app/api/v1/locations.py`, `app/schemas/catalog.py`, `app/repositories/catalog.py`, `app/services/catalog.py`, `app/core/logging.py`, plus `tests/test_geospatial.py`. New mobile modules are `services/location/{deviceLocationService,locationController,routingService,directionsService}.ts`, `services/campusService.ts`, `store/{LocationProvider,DiscoveryProvider}.tsx`, `utils/geospatial.ts`, `components/navigation/{mapModel.ts,CampusMap.web.tsx}`, and `components/location/{LocationPermission,DiscoveryFilters,WalkingRouteSummary}.tsx`. Existing map, home, Explore, detail, directions, recommendation, filter, card, DTO and root-provider files were updated. Package locks, Expo config, environment example, tests, README and validation docs were updated.
5. **Endpoint:** public `GET /api/v1/locations/nearby` returns complete location cards plus `distance_meters`; existing `/me` favorites remain authenticated.
6. **Queries:** parameterized geography origin with longitude first; `ST_DWithin` radius; `ST_Distance` meters; deterministic distance/ID ordering; shared SQL catalog filters; bounded bulk relationship loads.
7. **Database/index:** existing generated SRID 4326 geography and GiST index reused. No migration required; Alembic reports no schema drift. No user coordinate columns or history tables added.
8. **Mobile location:** centralized controller, balanced one-shot Expo Location read, 15-second read timeout, two-minute memory cache, accuracy/timestamp tracking, stale/invalid result rejection, duplicate-read suppression and late-result protection.
9. **Permission behavior:** explanation and explicit Enable Location/Not Now; no startup OS prompt. Denial and services failure leave campus browsing available. Only dismissal persists. Backgrounding, expiry and account changes clear position and route cache. Generated iOS permissions omit Always and motion access.
10. **Distance/routes:** PostGIS geodesic distance is labeled straight-line. Detail locally computes geodesic distance from the same position. Only actual routes from an optional OSRM-compatible pedestrian service supply walking times. Selected destinations and up to three recommendation candidates may request routes; missing configuration/errors/rate limits fall back safely. Recommendations disclose their geographic-radius fallback.
11. **Environment:** Optional `EXPO_PUBLIC_MAP_STYLE_URL` and `EXPO_PUBLIC_WALKING_ROUTE_URL` replace the former Mapbox token. Existing API/Supabase variables remain.
12. **External setup:** no map account or key is needed for the default style. OpenFreeMap has no uptime guarantee; operators can configure or host another compatible style for production.
13. **Executed validation:** 84 backend tests; 29 mobile tests; six Playwright journeys; one separate live OpenFreeMap browser journey; Ruff, TypeScript, ESLint and Prettier passed; Expo Doctor 21/21; all-platform bundle export succeeded; native introspection and iOS/Android prebuild succeeded; Alembic upgrade/check succeeded. Manual API smoke test returned three correctly ordered results and verified redacted access logs. See [exact commands/results](VALIDATION.md).
14. **Limitations:** live web rendering is verified; native visual/device QA is pending. iOS build compiled the MapLibre module but failed in Expo Constants' generated build script because it mishandles spaces in this workspace path (`/Users/junaid/Desktop/vs code projects/...`). No walking time without a configured pedestrian routing service. No viewport search, advanced marker clustering, indoor/floor routing or holiday hours. Discovery currently caps results at 100 zones.
15. **Test location:** inject 38.8315/-77.3075 via iOS Simulator Features → Location or Android Emulator Extended Controls → Location, then enable location from Home. Browser localhost supports devtools Sensors. Physical devices need a reachable LAN API URL and foreground permission. Deny permission and verify campus browsing remains available.
16. **Test map:** `cd mobile && npm ci && npx expo prebuild`, then `npx expo run:ios` or `npx expo run:android`; use `npx expo start --dev-client` afterwards. Web: `npm run web`; automated live check: `npx playwright test -c playwright.live.config.ts`. Select a building/floor, inspect preview, favorite it, open detail/directions, recenter and compare shared Map/Explore filters. Full instructions are in [geospatial.md](geospatial.md).
17. **Still demo:** occupancy and forecast seed data, illustrative photos, session-only check-ins/reports, sample alerts and simple recommendation scores. No live crowd or ML claim is introduced.
18. **Phase 5 interfaces:** existing occupancy DTO/source fields, authenticated user/favorite boundaries, explicit zone selection and service/repository separation remain ready for future real reporting. No Phase 5 submissions, Redis, reliability, background tracking, push or production deployment was added.
